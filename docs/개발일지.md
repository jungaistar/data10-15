## 왜 이렇게 했나

- **SheetJS 무료판은 서식을 쓰지 못합니다.** 읽은 양식을 고쳐 다시 쓰면 글꼴·테두리·색이 사라집니다(서식 쓰기는 유료판). 「기존 지정 양식에 맞춰」가 제출 글의 핵심이라, 라이브러리로 다시 쓰는 대신 xlsx 를 zip 으로 열어 **`{{키}}` 가 적힌 칸의 값만** 바꿨습니다. zip 을 여닫는 것은 SheetJS 에 들어 있는 CFB 를 썼고, 칸의 스타일 번호(s)는 건드리지 않습니다. 시험에서 채우기 전후 스타일 번호와 styles.xml 이 같은 것을 확인합니다.
- **반복 줄은 「빈 줄 먼저, 모자라면 끼우기」.** 회사 양식은 대개 표 줄을 몇 줄 그려 두고 아래에 합계 줄이 있습니다. 빈 줄을 먼저 쓰면 양식 모양이 그대로이고, 넘칠 때만 줄을 끼웁니다. 끼울 때는 아래 줄·병합·조건부 서식·인쇄 영역·그림(직인) 앵커를 함께 내리고, 범위 끝이 표 마지막 줄에 닿은 `SUM` 은 늘립니다. 엑셀의 「행 삽입」도 범위 바로 아래에 끼우면 SUM 을 늘리지 않는데, 그러면 합계가 틀리므로 여기서는 늘리게 했습니다.
- **칸이 키 하나면 숫자로.** `{{총액}}` 만 적힌 칸은 숫자로 넣어 양식의 `#,##0` 형식이 그대로 쓰이고 엑셀에서 다시 계산할 수 있습니다. 글과 섞이면 쉼표를 넣은 글자로 넣습니다. 달러 협력사는 양식의 `#,##0` 이 618.38 을 618 로 보이게 하므로, 그 칸의 스타일을 복제해 표시 형식만 `#,##0.00` 으로 바꾼 새 스타일을 붙입니다(원래 스타일은 그대로).
- **합의금액은 칸 우선.** 합의금액은 협상 결과이므로 계산값보다 엑셀에 적힌 값을 믿습니다. 비어 있을 때만 청구금액 × 부담 비율로 계산하고 「참고」로 표시합니다. 두 값이 허용 차이(기본 10원)를 넘게 다르면 「주의」 — 비율을 고치지 않고 금액만 바꾼 경우를 잡으려는 것입니다. 합의금액이 청구금액보다 크면 「확인 필요」로 두고, 그런 협력사는 처음에 문서 만들기 선택을 꺼 둡니다.
- **번호는 확정할 때만.** 미리 보기에서는 번호를 이력에 쓰지 않고, 엑셀 내려받기·인쇄를 할 때 확정합니다. 같은 협력사·같은 내용(행·금액이 같음)을 다시 내면 같은 번호(재발행)이고, 내용이 바뀌면 새 번호를 주고 이전 번호는 「대체됨」으로 남깁니다. 취소 표시한 번호는 다시 쓰지 않습니다 — 번호가 문서 대장의 기준이기 때문입니다.
- **PDF 는 두 갈래.** 브라우저만으로는 엑셀 서식을 그대로 PDF 로 바꿀 수 없어, 도구가 그리는 인쇄용 기본 양식(한 문서 한 쪽)을 「PDF로 저장」하게 하고, 양식 그대로의 PDF 는 내려받은 엑셀에서 저장하도록 안내했습니다. 자동 변환은 사내 서버 여부(10장 ⑤)를 확인한 뒤 2단계입니다.
- **여러 파일은 zip 하나로.** 협력사 여러 곳을 한 번에 받으면 브라우저가 파일마다 허락을 묻습니다. SheetJS 의 zip 쓰기는 한글 파일 이름을 깨뜨려(UTF-8 표시를 켜지 않음) 무압축 zip 을 직접 만들었습니다(이름 UTF-8 표시, CRC32 — 표준 검사값 `123456789 → CBF43926` 으로 확인).

## 사고와 교훈

- 처음 달러 인보이스를 PDF 로 바꿔 보니 618.38 이 618 로 찍혀 있었습니다. 값은 맞게 들어갔는데 양식의 표시 형식 때문이었습니다. 「값이 맞다」와 「보이는 것이 맞다」는 다르다는 것을 화면(PDF)을 보고서야 알았고, 소수 스타일 복제를 넣고 시험을 더했습니다.
- 브라우저 점검에서 zip 안 이름을 앞에서부터 서명으로 찾았더니 `xl/_rels/workbook.xml.rels` 가 나왔습니다. 안에 든 xlsx 도 zip 이라 그 안의 서명까지 잡힌 것입니다. 끝의 중앙 디렉터리에서 읽도록 고쳤습니다 — 검사기 쪽 결함이었습니다.
- 390px 인쇄 화면에서 문서가 가로로 넘쳤습니다. 격자(grid)의 칸은 기본 최소 너비가 내용 크기라 넓은 표가 칸을 밀어낸 것으로, `min-width: 0` 과 표 감싸기(가로 스크롤)로 고쳤습니다.
